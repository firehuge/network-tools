# Model and lifecycle data

All model data lives in `catalog/models.json`, generated by `tools/build_catalog.py`.
Every model lists the sources it came from, and the page links them on step 2.
No figure is made up: when a datasheet does not publish a number, the field is empty and the
page says **not published**.

## Sources

| Key | Source |
|---|---|
| summary | Palo Alto Networks *NGFW Specifications and Features Summary* (PAN-OS 12.2 edition) |
| eol | [Hardware End-of-Life Dates](https://www.paloaltonetworks.com/services/support/end-of-life-announcements/hardware-end-of-life-dates) |
| compat | [Compatibility Matrix: supported PAN-OS by model](https://docs.paloaltonetworks.com/compatibility-matrix/supported-os-releases-by-model/palo-alto-networks-next-gen-firewalls) |
| ds400, ds1400, ds3200, ds5200, ds5400, ds800, ds220r, ds7000 | Series datasheets (ports, HA ports, legacy figures) |
| vsys | [Platform Support and Licensing for Virtual Systems](https://docs.paloaltonetworks.com/ngfw/administration/virtual-systems/platform-support-and-licensing-for-virtual-systems) |
| vm_models, vm_req, vm_mem, vm_vsys, vm_ds | VM-Series models, system requirements, memory-based limits (11.2+), vsys on VM, legacy datasheet |
| hw400, hw500, ds500, hw1400, hw3400, ds3400, hw3200, hw5200, hw5400, hw800, hw7000, haports | Hardware reference guides and datasheets for power supplies (count, wattage, inlet) and dedicated HA ports |

Full URLs are in the `sources` block of `catalog/models.json`.

## What the numbers mean

- **Firewall throughput** is the vendor "appmix" figure (App-ID + logging).
  **Threat Prevention throughput** adds IPS, antivirus, anti-spyware, WildFire, file blocking and logging.
  Real traffic can run above or below these; they are for comparing models.
- **Sessions** and **new sessions/sec** are datasheet maximums.
- **Lifecycle** (currently sold, end-of-sale announced, end of sale, end of life) is worked out in
  the page from the dates against today's date, so it stays right without a rebuild.
- **Port lists** are in datasheet order. Only the PA-440 numbering has been checked on hardware.

## Live update

When online, the page tries to fetch a newer catalog from:

```
https://raw.githubusercontent.com/firehuge/network-tools/main/pan-physical-upgrade/catalog/models.json
```

It uses that copy only if its `data_as_of` date is the same or newer than the bundled one.
Override the URL with `?catalog=<url>`, or skip the check with `?offline`.
You can also load a JSON file with **Catalog file** in the header.

## Refreshing the data

1. Check the end-of-life page and the latest specifications summary for new models or dates.
2. Edit the tables in `tools/build_catalog.py` (each row keeps its source keys) and bump `DATA_AS_OF`.
3. `npm run build && npm test`.
4. Open a pull request. Once merged into the public repo, every copy of the page picks it up online.

## Readiness-check sources

| Key | Used for |
| --- | --- |
| `lim_mirror` | Capacity limits and rack/weight/airflow/power values for PA-400/800/1400/3400/5400 (reseller copy of the Palo Alto series datasheet tables; older revision) |
| `kb_gp`, `kb_rules` | GlobalProtect tunnel limits and legacy rule-object limits (Palo Alto KB) |
| `pc_tool` | Where to check every limit the tool does not have |
| `upgrade_path`, `upgrade_notes`, `upgrade_panorama` | Skip Software Version Upgrade, HA one-feature-release rule, Panorama version rule, PA-5450 and multi-vsys notes |
| `vm_lacp`, `vm_jumbo`, `decrypt_mirror` | VM-Series LACP, jumbo frame and Decrypt Mirror limits |

PSU wattage and inlet types come from the hardware guides (`hw*` keys) and datasheets (`ds*` keys). Each row in the tool links its source. Nothing is fetched at run time.
